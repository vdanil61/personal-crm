# Design

## Context

Зачем фича — в `proposal.md`, что должно получиться — в `specs/keep-in-touch/spec.md`. Макеты экранов — на холсте https://claude.ai/artifact/AbVUpgB8A4UicGStVQw35h, копия — в `mockups/`.

Как устроено сейчас:

- Таблица `contacts` (имя, кто это, откуда знакомы, телефон, почта, `created_at`, `updated_at`) и таблица `notes` (текст, `created_at`, ссылка на контакт). Заметки только добавляются: изменить или удалить заметку нельзя. Индекс (указатель для быстрого поиска) `notes_contact_id_created_at_idx` уже позволяет быстро найти последнюю заметку контакта.
- Главная (`src/app/page.tsx`) — серверная страница: заголовок и кнопка «Добавить контакт», под ними прилипающее поле поиска со счётчиком, ниже список. Поиск хранится в адресе (`?q=`), страница пересобирается на сервере при каждом изменении.
- Форма контакта (`contact-form.tsx`) общая для добавления и изменения; поля перечислены в `contactFields` и проверяются схемой `contactInputSchema` (`src/lib/validation.ts`).
- Удаление с отменой: сервер отдаёт браузеру снимок контакта с заметками, «Отменить» отправляет его обратно (`deleteContact` / `restoreContact`, проверка формы снимка — `contactSnapshotSchema`). В общем списке строка удалённого контакта исчезает сразу, не дожидаясь сервера (`useOptimistic` в `contact-browser.tsx`), фокус клавиатуры переходит на соседнюю строку.
- Все действия (`createContact`, `updateContact`, `addNote`, удаление, отмена) уже вызывают `revalidatePath("/", "layout")` — главная после них пересобирается со свежими данными.
- Автотестов в проекте нет; проверка — руками по сценариям спеки, плюс `pnpm lint` и `pnpm build`.

## Goals / Non-Goals

**Goals:**

- Два новых поля в базе, без переноса или пересчёта существующих данных.
- «Последнее общение» не хранится отдельно, а считается из заметок и отметки при каждом открытии главной — нечему рассинхронизироваться.
- Отметить «Связался» — одно нажатие, строка исчезает сразу, без ожидания сервера.
- Старая версия приложения (после ручного отката кода) работает с новой базой без ошибок.

**Non-Goals:**

- Ускорение для десятков тысяч контактов: приложение личное, контактов сотни, максимум тысячи.
- Исправление часового пояса дат (см. «Риски»).

## Decisions

### 1. Два поля в контакте: частота и время отметки

- `contacts.contact_frequency` — тип `text`, может быть пустым (`NULL` = «не задано»). Допустимые значения — `week`, `month`, `quarter`, `year`, их охраняет ограничение в базе (`CHECK`-ограничение: база сама не даст записать другое значение) `contacts_contact_frequency_check`. В Drizzle — `text("contact_frequency", { enum: [...] })` и `check(...)` в описании таблицы.
- `contacts.last_contacted_at` — `timestamp with time zone`, может быть пустым. Время последнего нажатия «Связался»; каждое нажатие перезаписывает его. В Drizzle — `timestamp("last_contacted_at", { withTimezone: true })`.

Почему не так:

- Перечисление Postgres (`pgEnum`, отдельный тип данных) для частоты — его труднее менять и удалять при откате, а выгоды для четырёх значений нет.
- Число дней (`7`, `30`, `90`, `365`) — ломает календарные месяцы: «раз в месяц» от 31 января должен прийти в конце февраля, а не 2 марта.
- Отметка как автоматическая заметка «Связались» — так решили не делать: заметки засорялись бы одинаковым текстом, а удалить заметку в приложении нельзя.
- Отдельная таблица отметок (история) — история не нужна, хватает времени последней.

Список значений частоты и подписи к ним («Раз в месяц» для формы, «раз в месяц» для карточки и блока) — в одном месте, `src/lib/contact-frequency.ts`: и форма, и проверка, и запрос берут их оттуда.

### 2. Кто просрочен — считает база при каждом открытии главной

Новая функция `listOverdueContacts()` в `src/lib/contacts.ts`. Для каждого контакта с заданной частотой:

- последнее общение = более позднее из «время последней заметки» и `last_contacted_at` (`greatest(...)` в Postgres пропускает пустые значения); если пусто и то и другое — `contacts.created_at`;
- срок = последнее общение + период (`interval '7 days'`, `'1 month'`, `'3 months'`, `'1 year'`); календарные месяцы Postgres считает сам (31 января + месяц = 28 или 29 февраля);
- просрочен, если срок раньше текущего момента;
- порядок: по сроку от самого раннего (он и есть «самый просроченный»), затем по имени в русском порядке (как в списке), затем по `id`.

Функция возвращает всех просроченных (без ограничения в 5): `id`, `name`, частоту и время последнего общения — только из заметок и отметок, без `created_at` (пусто → «ещё не связывались»). Последнюю заметку ищет подзапрос по существующему индексу `notes(contact_id, created_at)`.

Почему не хранить «последнее общение» одним полем, которое обновляют и заметка, и кнопка: его пришлось бы обновлять в `addNote`, при отмене удаления и в тестовых данных — несколько мест, где легко ошибиться. Расчёт на лету для сотен контактов занимает миллисекунды.

### 3. Действие сервера «Связался»

Новое действие `markContacted(contactId)` в `src/app/actions.ts`, по образцу `addNote`:

- проверяет `contactId` (`idSchema`);
- `update contacts set last_contacted_at = now(), updated_at = now() where id = ...` — время берёт база, как и у заметок, поэтому даты заметок и отметок сравнимы;
- контакта уже нет → «Этот контакт больше не существует.»; ошибка базы → «Не удалось отметить. Проверьте, что база данных запущена, и попробуйте ещё раз.» В журнал — только класс и код ошибки (`describeError`), как у остальных действий;
- `revalidatePath("/", "layout")`.

Отмены нет — так решено. Повторное нажатие (например, в другой вкладке) просто ещё раз записывает текущее время.

### 4. Блок — серверная часть плюс браузерная

- `src/app/page.tsx`: новый серверный кусок `KeepInTouch` в своём `Suspense` (заглушка при загрузке — пусто, чтобы не мигал скелетон там, где блока может не быть). Он читает `?q=` из адреса: поиск не пустой — ничего не рисует; иначе зовёт `listOverdueContacts()`; список пуст — ничего не рисует.
- Место — между заголовком «Контакты» с кнопкой «Добавить контакт» и прилипающим полем поиска. Под поиском блок встать не может: строка «1 000 контактов» с выбором размера страницы относится к списку и должна быть прямо над ним.
- `src/components/contacts/keep-in-touch.tsx` (браузерный компонент), по макету:
  - заголовок «Пора связаться» и число в маленькой плашке;
  - строка — ссылка на `/contacts/<id>` (аватар, имя, «раз в месяц · связались 22 августа» / «ещё не связывались») и рядом, вне ссылки, кнопка «Связался». От ширины `sm` (640 px) и шире — кнопка с рамкой, галочкой и текстом; уже — квадратная кнопка 44×44 px только с галочкой. Доступное имя кнопки — «Связался: Анна Смирнова», чтобы программы чтения с экрана различали строки;
  - нажатие: строка скрывается сразу (`useOptimistic`, как удаление в общем списке), фокус переходит на кнопку «Связался» соседней строки, затем вызывается `markContacted`; успех — всплывающее сообщение «Отмечено: Анна Смирнова» (`toast.success`, без кнопки «Отменить»); ошибка — `toast.error` с текстом от сервера, строка возвращается, когда страница обновится;
  - число в заголовке и «Показать всех (N)» считаются по видимым строкам, поэтому после отметки сразу уменьшаются; осталось 5 и меньше — кнопки нет; не осталось никого — блок не рисуется;
  - «Показать всех (N)» / «Свернуть» — состояние только в браузере (`useState`), после обновления страницы снова 5.
- Сервер отдаёт сразу всех просроченных, а не 5 + отдельный запрос по кнопке: просроченных обычно десятки, а кнопка тогда срабатывает мгновенно.
- Вид строк — как у строк общего списка (`ContactAvatar`, те же отступы и токены), без кнопки удаления.

### 5. Дата «22 августа»

Новая функция `formatDayMonth(date, now)` в `src/lib/format.ts`: «22 августа», а если год не текущий — «3 марта 2025». Форматирует сервер, так же как существующая `formatDateTime`.

### 6. Поле в форме — выпадающий список shadcn/ui

Компонент `select` из shadcn/ui добавляется командой `pnpm dlx shadcn@latest add select` в `src/components/ui/select.tsx`. Он построен на `@base-ui/react`, которая уже стоит в проекте, — новой библиотеки нет. У списка задаётся `name="contactFrequency"`, значение уходит с формой как обычное поле; «Не задано» — пустая строка, которая превращается в `NULL`, как у остальных необязательных полей.

Поле стоит последним в форме, после телефона и почты. В `contactFields`, `ContactFormValues` и `contactInputSchema` добавляется `contactFrequency`: пустая строка или одно из четырёх значений, иначе ошибка «Выберите частоту из списка».

Почему не обычный `<select>` браузера: он выглядит иначе, чем остальные поля, и не берёт шрифты и цвета из дизайн-токенов.

### 7. Карточка и отмена удаления

- Карточка (`src/app/contacts/[id]/page.tsx`): ещё один `InfoItem` «Как часто общаться» во всю ширину после телефона и почты; пусто — «не указано», как у других полей. В `EditContactDialog` передаётся текущее значение. Отметка «Связался» в карточке не показывается.
- Отмена удаления: `deleteContact` уже берёт контакт целиком (`select()`), так что оба поля попадают в снимок сами. В `contactSnapshotSchema` добавляются `contactFrequency` (одно из четырёх значений или пусто) и `lastContactedAt` (дата или пусто); если поля в снимке нет — считается пустым, чтобы снимок, сделанный старой версией, не ломал отмену.

## Risks / Trade-offs

- [Случайное нажатие «Связался» нельзя отменить] → Так решено. Контакт вернётся в блок только через срок. Кнопка стоит отдельно от ссылки на карточку, с отступом, чтобы не задеть её, открывая карточку.
- [Поле поиска прыгает вверх, когда блок прячется во время ввода] → Это следствие решения «блок над поиском и прячется при поиске». Курсор и введённый текст остаются в поле: оно не пересоздаётся. Если будет мешать — обсудить другое место блока.
- [Даты считаются в часовом поясе сервера] → На сервере в Docker, скорее всего, UTC (Москва − 3 часа): заметка в 01:00 по Москве 23 августа покажется как «22 августа». Так же уже ведут себя даты заметок в карточке. Исправлять — отдельной правкой для всего приложения.
- [Сотни просроченных контактов] → Страница станет тяжелее, но до раскрытия видно только 5. При личном использовании маловероятно.
- [Срок наступает с точностью до минуты] → «Раз в неделю» от заметки в среду в 15:00 сработает в следующую среду в 15:00, а не с утра. Для напоминалки без уведомлений это незаметно.

## Migration Plan

**Миграция `drizzle/0001_<имя от drizzle-kit>.sql`** — создаётся командой `pnpm db:generate` из схемы:

1. `ALTER TABLE "contacts" ADD COLUMN "contact_frequency" text;` — новое пустое поле. Существующие контакты получают `NULL` = «не задано». Postgres добавляет пустое поле без перезаписи таблицы — мгновенно.
2. `ALTER TABLE "contacts" ADD CONSTRAINT "contacts_contact_frequency_check" CHECK (...)` — разрешены только четыре значения или пусто. Существующие строки проходят проверку (у всех пусто).
3. `ALTER TABLE "contacts" ADD COLUMN "last_contacted_at" timestamp with time zone;` — новое пустое поле, у всех существующих контактов пусто = «Связался» ещё не нажимали. Тоже мгновенно.

Существующие данные не меняются: имена, заметки, даты остаются как были. Блок «Пора связаться» сразу после выкатки пуст — частоты ещё ни у кого нет.

**Выкатка** — обычная: merge в main → образ → разовый контейнер применяет миграцию → стартует новый образ → проверка `/health`.

**Откат:**

- Кода (`rollback.sh`, запускаете вы): поля в базе остаются, старая версия их не видит и работает как раньше. Частоты и отметки сохраняются и вернутся при следующей выкатке новой версии. Одна оговорка: если в старой версии удалить контакт и нажать «Отменить», его частота и отметка пропадут.
- Базы (убрать поля совсем) — не нужен, поля безвредны. Если всё же понадобится — вручную: `ALTER TABLE contacts DROP CONSTRAINT contacts_contact_frequency_check; ALTER TABLE contacts DROP COLUMN contact_frequency; ALTER TABLE contacts DROP COLUMN last_contacted_at;` и удалить запись о миграции `0001` из журнала миграций Drizzle. Все заданные частоты и отметки при этом теряются — только с вашего согласия.
