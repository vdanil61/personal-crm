# Личная CRM

Контакты людей, которых я знаю лично. Идея и ограничения — в `specs/01-продуктовая-идея.md`.

Что умеет:

- список контактов по алфавиту, по 50 на странице (можно выбрать 10, 20 или 50 — справа над списком), внизу — переключатель страниц;
- поиск по имени по всем контактам (без учёта регистра, «е» и «ё» — одно и то же); найденное тоже разбито на страницы;
- добавить контакт: имя, кто это, откуда знакомы, телефон, почта и как часто общаться (раз в неделю, месяц, квартал, год или «не задано»);
- карточка контакта: исправить данные, дописать заметку после разговора (заметки идут с датой, новые сверху).
- удалить контакт из карточки или из списка — вместе с заметками; 10 секунд можно нажать «Отменить» и вернуть всё как было.
- блок «Пора связаться» над списком: люди, с которыми не общался дольше заданной частоты, самые просроченные сверху (сначала 5, остальные — по «Показать всех»). Общение — это заметка или кнопка «Связался» в строке блока: она убирает человека из блока, не создавая заметку. Пока идёт поиск, блока нет.
- группы: страница «Группы» (кнопка «Группы» на главной рядом с заголовком) — пять готовых групп («Аналитики», «Друзья», «Знакомые», «Семья», «Теннис») и свои; у каждой видно, сколько в ней людей. Группу можно создать, переименовать и удалить; название — до 50 символов, «Семья» и «семья» (как и «Ёлки» и «Елки») считаются одним названием. При удалении сначала спрашивают, потом 10 секунд можно нажать «Отменить» — группа вернётся с теми же людьми; сами люди при удалении группы остаются в контактах.
- группы у человека: в форме «Добавить контакт» и «Изменить» есть поле «Группы» — нажмите нужные (можно несколько или ни одной); в карточке контакта строка «Группы» и кнопка «Изменить группы»: открывается список с флажками, каждая отметка сохраняется сразу, без кнопки «Сохранить». Если удалить контакт и нажать «Отменить», он вернётся в те же группы.
- фильтр по группам над списком: «Все», каждая группа и «Без группы». Если выбрать несколько групп, останутся люди, которые есть во всех них сразу. Фильтр работает вместе с поиском и счётчиком («Найдено: 3 из 120»), хранится в адресе страницы (обновили страницу или открыли ссылку — фильтр тот же) и действует и на общий список, и на блок «Пора связаться»: в нём остаются только подходящие люди. В строке каждого человека видны метки его групп: нажатие на метку добавляет эту группу к фильтру, а метка в карточке открывает главную только с этой группой.

Данные лежат в базе на этом компьютере, поэтому в любом браузере видны одни и те же контакты.
Входа по паролю нет, поэтому локальная версия открывается только на этом компьютере (`127.0.0.1`), другим устройствам в сети она не видна.

Версия на сервере — <https://app.percrm.ru>, со своей базой. Пароля там тоже нет: открыть и изменить контакты может любой, кто знает адрес. Как она обновляется — в разделе «Выкатка на сервер».

## Что нужно

- Docker Desktop (должен быть запущен)
- Node.js 24 и pnpm
- OpenSpec — для работы над фичами с агентом (см. «Как делаем фичи»)

## Первый запуск на новом компьютере

1. Скопировать `.env.example` в `.env` и заполнить значения (пароль — любой длинный случайный).
2. Установить зависимости:

   ```sh
   pnpm install
   ```

3. Запустить базу:

   ```sh
   docker compose up -d --wait
   ```

4. Создать таблицы в базе:

   ```sh
   pnpm db:migrate
   ```

5. По желанию — наполнить базу тестовыми данными (1000 контактов с заметками; примерно две трети людей лежат в одной-двух из пяти готовых групп, остальные без групп). Работает только на пустой базе, существующие контакты не трогает:

   ```sh
   pnpm db:seed
   ```

6. Запустить приложение и открыть <http://localhost:3000>:

   ```sh
   pnpm dev
   ```

## Каждый день

1. Запустить Docker Desktop — база стартует вместе с ним. Если её останавливали командой `docker compose down`, запустить снова: `docker compose up -d --wait`.
2. `pnpm dev` и открыть <http://localhost:3000>.
3. Остановить приложение — `Ctrl + C` в терминале.

## Как проверить, что всё работает

1. Открыть <http://localhost:3000> — видны первые 50 контактов, их общее количество и переключатель страниц внизу. «Дальше» открывает следующие 50. «Показывать по 10» справа над списком — на странице 10 контактов, страниц становится больше.
2. «Добавить контакт» → заполнить имя → «Добавить». Откроется страница списка, где оказался новый контакт: список прокрутится к нему и подсветит его.
3. Ввести часть имени в поиск → открыть карточку → написать заметку → «Добавить заметку».
4. Обновить страницу — заметка на месте.
5. Открыть тот же адрес в другом браузере (например, Safari) — те же контакты и та же заметка.
6. В карточке контакта нажать «Удалить» — откроется тот же список, где вы были, контакта в нём нет. Внизу 10 секунд висит «Контакт удалён» с кнопкой «Отменить»: она возвращает контакт со всеми заметками и снова открывает карточку.
7. В списке навести мышь на строку — справа появится корзина. Нажать — строка сразу пропадёт, «Отменить» вернёт её на место. На телефоне корзина видна всегда.
8. Открыть контакт с давней заметкой (больше месяца назад) → «Изменить» → «Как часто общаться: Раз в месяц» → «Сохранить». На главной над поиском появится блок «Пора связаться» с этим человеком.
9. Нажать у него «Связался» — он сразу пропадёт из блока, внизу появится «Отмечено: <имя>». В его карточке заметок столько же, сколько было.
10. Задать «Раз в месяц» другому контакту с давней заметкой — он в блоке. Открыть его из блока, написать заметку, вернуться на главную — в блоке его больше нет.
11. Нажать «Группы» на главной — видны пять готовых групп с числом людей. «Создать группу» → «Работа» → «Сохранить»: группа встала в список по алфавиту. «Удалить» у «Работа» → «Удалить»: внизу 10 секунд висит «Группа «Работа» удалена» с кнопкой «Отменить».
12. Положить двух людей в «Друзья», одного из них ещё в «Теннис» (в карточке: «Изменить группы» → поставить флажки). На главной выбрать «Друзья» и «Теннис» — виден один. Обновить страницу — фильтр тот же. Нажать «Без группы» — этих двоих в списке нет.

## Команды

| Что сделать | Команда |
|---|---|
| Запустить приложение для работы | `pnpm dev` |
| Собрать и запустить «боевую» версию (быстрее) | `pnpm build`, затем `pnpm start` |
| Создать или обновить таблицы в базе | `pnpm db:migrate` |
| Наполнить пустую базу тестовыми контактами | `pnpm db:seed` (или `pnpm db:seed 200` — другое количество) |
| После изменения схемы в `src/db/schema.ts` — подготовить миграцию | `pnpm db:generate` |
| Проверить код | `pnpm lint` |
| Запустить автотесты | `pnpm test` |

Для `pnpm test` нужна запущенная база (`docker compose up -d --wait`). Тесты идут в отдельной базе `<имя вашей базы>_test` в том же контейнере: `pnpm test` сам создаёт её и применяет миграции, а рабочая база и её контакты не трогаются. Если база не запущена, `pnpm test` сразу пишет, что подключиться не удалось, и подсказывает команду запуска. Строку «No test files found» ниже можно не читать: её добавляет сам Vitest.

## База данных

PostgreSQL работает локально в Docker. Настройки подключения лежат в `.env`, его нет в git.
Приложение берёт из `.env` те же `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` и `POSTGRES_PORT`, что и Docker.
Если в `.env` задан `DATABASE_URL`, используется он.

Полезные команды:

| Что сделать | Команда |
|---|---|
| Запустить базу | `docker compose up -d --wait` |
| Посмотреть, работает ли | `docker compose ps` (статус `healthy` — всё хорошо) |
| Зайти в базу консолью | `docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'` |
| Остановить базу (данные сохранятся) | `docker compose down` |

Данные хранятся в Docker-томе `personal-crm_db-data` и переживают остановку и перезапуск.
Команда `docker compose down -v` **удалит все данные** базы.

## Как делаем фичи

Фичи проектируем с агентом через [OpenSpec](https://openspec.dev): сначала требования и план, потом код. Документы пишутся по-русски.

Установить OpenSpec на новом компьютере (один файл, ставится в `~/.local/bin`):

```sh
curl -fsSL https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/scripts/binary/install.sh | sh
```

Команды в Claude Code:

| Что сделать | Команда |
|---|---|
| Обдумать идею, ничего не меняя | `/opsx:explore` |
| Описать фичу: требования, план, задачи | `/opsx:propose <что хотим>` |
| Сделать фичу по плану | `/opsx:apply` |
| Поправить требования или план | `/opsx:update` |
| Закрыть сделанную фичу (требования переедут в `openspec/specs/`) | `/opsx:archive` |
| Пересказать фичу простыми словами | `/feature-overview` |

Обновить OpenSpec: `openspec install`, затем в папке проекта `openspec update`.

## Выкатка на сервер

Каждый push в `main` (в том числе merge pull request) сам выкатывает новую версию:

1. GitHub Actions собирает Docker-образ, тег — SHA коммита, и кладёт его в GHCR: `ghcr.io/vdanil61/personal-crm`.
2. Копирует файлы из `deploy/` на сервер и запускает `deploy.sh`:
   - разовый контейнер из нового образа применяет миграции базы и завершается. Если миграции упали — новая версия не стартует, работает старая;
   - запускает новую версию приложения;
   - smoke-проверка: `/health` должен ответить 200;
   - удаляет старые образы, оставляет текущий и предыдущий.

Для pull request Actions только проверяет, что образ собирается, на сервер ничего не попадает.

Ход выкатки — в репозитории на GitHub: вкладка **Actions** → **Deploy**. Зелёная галочка — новая версия работает, красный крестик — выкатка упала: в логе видно, на каком шаге.

Проверить руками: открыть <https://app.percrm.ru/health> — должно быть `{"status":"ok"}`.

### Если выкатка упала

Автоматического отката нет. Откатиться на предыдущую версию — вручную, командой на своём компьютере:

```sh
ssh -t crm sudo -u deploy /home/deploy/personal-crm/rollback.sh
```

Откат возвращает только код: изменения базы (миграции) остаются.

### Тестовые данные на сервере

GitHub → **Actions** → **Seed test data** → **Run workflow**. Работает только на пустой базе, существующие контакты не трогает.

### Сервер

- Приложение работает от пользователя `deploy` в папке `/home/deploy/personal-crm`: там `compose.yaml` (проект `prod`), скрипты, `.env` с паролем базы (права 600, в git нет — образец в `deploy/.env.example`), история выкаток `releases.log`.
- nginx отправляет `app.percrm.ru` в приложение (`deploy/nginx/app.percrm.ru.conf`).
- Сервер подготовлен один раз скриптом `deploy/setup-server.sh` (пользователь `deploy`, ключ для GitHub, nginx).
- В настройках репозитория на GitHub: секрет `DEPLOY_SSH_KEY` (ключ, которым Actions заходит на сервер), переменные `DEPLOY_HOST` и `DEPLOY_KNOWN_HOSTS` (адрес сервера и его отпечаток).
